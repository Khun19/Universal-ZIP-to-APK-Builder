## Build pipeline

`Create Source Project` or `Import Source ZIP`
→ ZIP security validation
→ safe extraction
→ staged framework detection
→ framework-specific platform preparation
→ dependency/toolchain preparation
→ framework-owned build command
→ APK structural/manifest validation
→ SHA-256 and delivery.

## Framework-specific platform preparation

The `lib/platform-generators.ts` registry documents distinct adapter contracts:

- Native Android: validate the supplied Android project; do not replace it.
- Bare React Native: use a temporary project generated by a React Native Community CLI version compatible with the declared `react-native` version, then copy only `android/` if absent. Preserve user source files and validate native entry points and Gradle wiring.
- Expo: use Expo prebuild only when `expo` is explicitly declared.
- Capacitor: use Capacitor Android add/sync, after validating both config and dependency evidence.
- Flutter: use the selected Flutter SDK to create/recover only the Android platform while preserving Dart source and assets.
- React/Vite and plain web: use the dedicated WebView wrapper generator.
- Unknown/ambiguous: block and report evidence; never guess a framework.

## Safety and compatibility requirements

- Never overwrite user-owned app source to generate a platform.
- Generate missing platform files in a temporary directory first.
- Validate required outputs before copying generated files into the project.
- Keep backups if replacing an incompatible platform, and restore on failure.
- Pin or derive generator versions from the project's declared framework version; do not use an unbounded latest CLI.
- Record each preparation stage and its result in build logs.
- A successful detection or generator unit test is not proof of a successful APK build. Require an actual build, APK validation, and device install/launch/interaction evidence for device-level PASS.
