# RZ-BUILD — Scoped Implementation and Build

**Input:** approved milestone, frozen baseline, acceptance plan, cleanly understood Git status. **Action:** implement only approved scope; pause after implementation for RZ-CHECK source/type/unit tests; then build the actual candidate artifact; run required post-build checks; review exact changed files; commit/push the scoped change only after required local checks pass. **Output:** candidate source commit, build outputs, logs, and exact GitHub handoff. **Evidence:** changed-file list/diff, commands, exit codes, toolchain, test/build logs, commit SHA, push result, CI references. **Acceptance:** build outputs correspond to approved source and configuration; errors are not suppressed; unrelated changes are not included; exact pushed commit is recorded. **Owner:** implementer/build operator; source owner controls scope. **Status:** use RZ statuses. **Failure:** stay on same milestone; invoke RZ-DEV for a failed criterion; do not declare gate PASS. **Exit:** candidate is reproducible and handed to RZ-CHECK/RZ-ARTIFACT and exact-commit external validation as required.

Implementation, automated verification, Gradle/toolchain build, APK inspection, and phone runtime are distinct claims even when run in one shell session.
