# RZ-GATE — Milestone Decision

**Input:** approved milestone record, complete trace map, categorized evidence, regression outcomes, limitations. **Action:** evaluate each acceptance criterion independently against its required evidence and owner. **Output:** dated PASS/FAIL/BLOCKED decision and next authorized action. **Evidence:** completed `templates/GATE-EVIDENCE-TEMPLATE.md`, linked source commit/artifact/device evidence, reviewer identity. **Acceptance:** PASS only when every mandatory criterion is satisfied and the accountable human gate owner explicitly accepts the bundle; otherwise report FAIL (observed failed criterion), BLOCKED (unavailable prerequisite), and/or NOT VERIFIED (missing/insufficient evidence). **Owner:** accountable human gate owner; AI may prepare/review evidence but cannot attest to external events it did not observe. **Status:** RZ status semantics apply. **Failure:** FAIL/BLOCKED/NOT VERIFIED keeps the same milestone active or paused; route fixes through RZ-DEV and revalidate. **Exit:** PASS closes only this milestone and authorizes a separately defined next milestone; any other status authorizes no progression.

Build PASS, APK existence, install PASS, or launch alone cannot satisfy unrelated runtime/offline/feature criteria. Missing evidence is never PASS.
