# RZ-MILESTONE — One-Milestone Plan

**Input:** reviewed architecture/specification baseline and protected-milestone register. **Action:** define exactly one active milestone and its full acceptance/evidence plan. **Output:** approved milestone record using `templates/MILESTONE-TEMPLATE.md`. **Evidence:** owner decision, dependency readiness, requirement/test trace links, regression/security impact, and baseline commit/branch. **Acceptance:** all required fields are populated; criteria are objective and not weaker than requirements; test/build/artifact/Termux/runtime requirements and evidence sources are explicit; out-of-scope work is stated. **Owner:** milestone owner with human approval. **Status:** use RZ statuses. **Failure:** missing prerequisite or ambiguous criterion means BLOCKED/NOT VERIFIED and no implementation; revise through change control. **Exit:** exactly one milestone is authorized; no later milestone starts until its gate is PASS.

Required fields are the list in RZ-GOVERNANCE plus baseline commit/branch, stable REQ/SPEC IDs, risk/security applicability, gate owner/decision time, and change history. Use `N/A` with a rationale rather than leaving a blank.
