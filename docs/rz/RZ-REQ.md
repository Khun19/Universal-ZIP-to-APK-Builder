# RZ-REQ — Requirements

**Input:** approved objective and architecture constraints. **Action:** write stable, uniquely identified, testable functional, quality, security, compatibility, and operational requirements; identify exclusions and dependencies. **Output:** approved requirement baseline (`REQ-ID`s). **Evidence:** requirement review/disposition and links to stakeholder/source request. **Acceptance:** each in-scope requirement is unambiguous, measurable, feasible, and traceable; device/runtime claims state the required device/environment. **Owner:** requirements owner; human approves acceptance. **Status:** use RZ statuses. **Failure:** ambiguity returns to RZ-DEFINE/RZ-ARCH; missing stakeholder decision blocks exit. **Exit:** all requirement IDs approved and ready for technical specification.

Do not weaken a requirement after a failing result without approved change control.
