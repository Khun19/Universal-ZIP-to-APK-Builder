# RZ-RUNTIME — Physical Device Validation

**Input:** exact APK hash, runtime acceptance criteria, supported physical device, test procedure. **Action:** install the identified APK and exercise required launch, feature, permission, offline/network, persistence, and sustained-use behavior. **Output:** device result per criterion. **Evidence:** operator and date/timezone, model, Android/API, ABI, install source/result, installed package/version and APK hash, steps, observations, relevant logs/screenshots. **Acceptance:** every runtime criterion is directly observed on the required device; offline claims are tested with network unavailable; app remains open/functional as criteria require. **Owner:** phone operator supplies evidence; human gate owner verifies it. **Status:** use RZ statuses. **Failure:** actual crash/behavior failure is FAIL with captured evidence; unavailable device/access is BLOCKED; absent logs/observations are NOT VERIFIED. **Exit:** evidence maps to criteria and exact APK; otherwise gate remains open.

AI must not claim physical-device PASS from build output, APK inspection, emulator-only behavior, package registration, or user intention to test.
