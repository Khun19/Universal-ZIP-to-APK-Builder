# RZ-SPEC — Technical Specification

**Input:** approved REQ-ID baseline and architecture. **Action:** define implementation contracts, pipeline behavior, interfaces, errors, configuration, threat controls, test strategy, artifacts, and environment constraints needed to satisfy each requirement. **Output:** versioned technical specification with requirement links. **Evidence:** reviewed design details, examples/contracts, security applicability, and open-issue dispositions. **Acceptance:** every requirement is specified or explicitly justified N/A; failure behavior and observable evidence are defined; no hidden hosted/cloud dependency or unapproved scope. **Owner:** technical specification owner. **Status:** use RZ statuses. **Failure:** contradictions return to requirements/architecture review; unknown critical behavior blocks milestone planning. **Exit:** specification baseline approved for RZ-REVIEW.
